# Intent MILEAGE: правило по пробегу в решении по заявке

## 1. Замысел

Добавить в расчёт решения по заявке правило по пробегу: при пробеге свыше
400 000 км решение понижается с approve до review. В ответе API появляется
код причины такого даунгрейда.

## 2. Зачем

Экстремальный пробег — риск, не описываемый LTV: такие заявки не должны
получать автоматическое approve по одному LTV и уходят на ручную проверку.

## 3. Constraints

- Порог 400 000 км, граница включительная: 400 000 — решение без изменений,
  400 001 — правило срабатывает. («ответ в интервью»: «не больше 400 000 км»;
  подтверждено граничными тестами 399999/400000/400001 в `docs/plan/README.md:13`)
- Даунгрейд, не перекрытие: понижает только approve → review; LTV-reject
  остаётся reject, LTV-review остаётся review. («ответ в интервью»)
- Правило уровня решения, не валидации: пробег 400 001…500 000 — валидный
  вход. («код: `backend/src/Domain/ApplicationValidator.php:43-46`», лимит —
  `backend/config/rules.php:23`)
- Пробег обязателен: отсутствие поля — `ValidationException`, до правила
  решения не доходит. («код: `backend/src/Domain/ApplicationValidator.php:43`»)
- Новое поле ответа — код причины даунгрейда; заполняется только при
  понижении из-за пробега, иначе null. («ответ в интервью»)
- Порог хранится в `backend/config/rules.php`, не в коде. («код:
  `backend/config/rules.php`»)
- `approved_limit` при даунгрейде — 0. («код:
  `backend/src/Domain/AssessmentService.php:39`»)
