# grill_MILEAGE: лог интервью по intent «правило по пробегу»

Дата: 2026-10-13. Режим Grill Me: вопросы по одному, только те, от которых
зависит реализация. Задано 4 из максимум 6.

## Закрыто без вопросов — видно из задачи и кода

- Граница 400 000 включительна: «не больше 400 000 км» в формулировке задачи;
  граничные тесты 399999/400000/400001 в `docs/plan/README.md:13`.
- Пробег не указан: `(int)($payload['mileage'] ?? -1)` даёт −1 и ошибку
  валидации до расчёта решения
  (`backend/src/Domain/ApplicationValidator.php:43-46`).

## Вопросы и ответы

1. Семантика «иначе review»: только даунгрейд approve → review или
   принудительный review поверх любого решения?
   **Ответ:** только даунгрейд approve → review; LTV-reject остаётся reject,
   LTV-review остаётся review.
2. Что из перечисленного точно вне scope: лимит валидации 500 000; новые
   поля в ответе; БД и фронтенд; LOAN-12?
   **Ответ:** отмечен только лимит валидации 500 000 — прочие пункты
   потребовали уточнения.
3. Уточнение по scope: что из неотмеченного реально входит в задачу?
   **Ответ:** новые поля в ответе (код причины даунгрейда). БД, фронтенд и
   LOAN-12 — вне задачи.
4. Формат нового поля: код причины даунгрейда, универсальный reason или
   булев флаг?
   **Ответ:** код причины даунгрейда — заполняется только при понижении
   approve → review из-за пробега, иначе null (пример из интервью:
   `review_reason` / `mileage_over_threshold`).
